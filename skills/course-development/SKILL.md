## 并行执行与交叉校验机制

### 并行Agent调用原则

当多个子任务**无依赖关系**时，使用 Agent 工具并行调度，而非串行执行：

```
Agent 1: 执行任务A
Agent 2: 执行任务B（与A无依赖）
→ 等待两者完成 → 合并结果
```

**可并行的典型场景：**
- 5W2H分析中，Why/Who/What/How/How much 各维度可并行分析
- SWOT的四象限可并行生成
- 课程命名可并行生成多个候选
- 问卷设计时，不同维度的题目可并行设计
- 教学方案的五阶段可并行设计
- 讲师手册的四个板块（开场语/破冰/互动/总结）可并行生成
- 案例手册和评估题集可并行汇编

**串行执行（有依赖关系）：**
- 课题分析 → 课程命名（命名依赖分析结论）
- 问卷设计 → 学员画像（画像依赖问卷数据）
- 边界界定 → 知识框架 → 大纲生成 → 逻辑校验（严格依赖链）
- 教学方案 → 方法线（方法线依赖方案）
- PPT骨架 → PPT内容（内容依赖骨架）

- 输出最终报告

用户确认后，使用 ExitPlanMode 退出。

**步骤4：并行设计问卷各维度题目**

```
Agent A (model: claude-sonnet-4-6):
  任务：设计"痛点调研"维度题目（3-4题）
  约束：遵循防伪装法则、测痛点法则
  输出：3-4道客观题

Agent B (model: claude-sonnet-4-6):
  任务：设计"AI能力水平"维度题目（3-4题）
  约束：遵循测水平法则（阶梯难度）
  输出：3-4道客观题

Agent C (model: claude-sonnet-4-6):
  任务：设计"学习期望"维度题目（3-4题）
  约束：遵循防伪装法则
  输出：3-4道客观题
```

合并去重，确保总题量10条左右。

**问卷设计核心法则：**

**法则1：防伪装**
- 绝对禁止"道德正确"选项
- 必须让所有选项看起来都是"无奈之举"或"行业内普遍做法"

**法则2：测痛点**
- 不要问"怎么看"，要问"时间花在哪了"或"卡在哪里最久"
- 行为轨迹不会骗人

**法则3：测水平**
- 设置"隐蔽的阶梯难度"
- 让选项呈现出"本能反应 → 经验主义套路 → 结构化专业思维"的阶梯

**问卷要求：**
- 3分钟内能完成
- 纯客观题
- 10条左右
- 前一题选项不影响后续问题作答

**完成后：** 使用 AskUserQuestion 询问用户是否需要调整问卷内容。

**步骤5（可选）：通过问卷星发布问卷**

如果用户需要将问卷发布到线上收集数据，使用问卷星MCP工具创建并发布：

```

```

如用户确认，执行以下流程：

1. **生成问卷JSON**：将设计好的10道客观题转换为问卷星JSON格式，使用 `create_survey_by_json` 工具创建问卷
2. **验证问卷**：使用 `get_survey` 工具确认问卷内容正确
3. **获取链接**：使用 `build_survey_url` 工具生成问卷链接和二维码，提供给用户
4. **告知用户**：提供问卷编辑链接（如需调整）和发布链接（供学员填写）

```
调用示例：
create_survey_by_json({
  title: "课程开发课前调研问卷",
  atype: 1,
  questions: [...]
})

build_survey_url({ mode: "edit", activity: vid })
build_survey_url({ mode: "publish", activity: vid })
```

**完成后：** 使用 AskUserQuestion 询问用户是否需要调整问卷内容或重新发布。

- 情境题的场景是否来自课前调研数据的真实痛点？
- 场景中引用的具体数据是否准确？
- 有没有编造调研中不存在的痛点数据？

**维度三：选项与难度对齐**
- 基础题：4个选项是否有3个干扰项具有合理性？
- 基础题：是否存在"送分题"（正确答案过于明显）？
- 情境题：4个选项之间的优劣差距是否足够小（需要真正思考）？
- 情境题：是否存在"明显错误"的选项（完全不符合常理）？
- 情境题：答案解析中是否包含利弊分析和风险提示？

**输出格式：**
表格：题号 | 维度一：目标对齐 | 维度二：数据对齐 | 维度三：难度对齐 | 问题（如有） | 修改建议

**完成后：** 使用 AskUserQuestion 询问用户是否需要根据校验结果调整测试题。
