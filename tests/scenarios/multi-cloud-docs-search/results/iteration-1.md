## REFACTOR Phase

### 发现的漏洞

| # | 漏洞 | 描述 | 修复方式 |
|---|------|------|---------|
| 1 | **知识替代** | agent 可能说"我知道价格，不需要查" | 规则 1：增加"禁止知识替代" |
| 2 | **外部搜索绕过** | 用 curl/wget/fetch 替代 WebSearch | 规则 2：明确列出所有被禁止的工具 |
| 3 | **部分覆盖** | 用户问多家厂商时只查一家 | 规则 3：增加"必须完整覆盖" |
| 4 | **精度降级** | 用户说"大概多少钱"就跳过工具 | 规则 4：增加"精度要求无关" |
| 5 | **partial/no_price 冲突** | "建议访问官网"与"禁止 fallback"矛盾 | 常见错误 3：明确"告知用户网址，不要自行搜索" |

### 新增的反制措施

1. **规则 1 强化**：必须**先**调用 MCP 工具，再基于结果回答。即使知道答案也要调用。
2. **规则 2 强化**：明确列出 curl、wget、fetch API、Bash 网络请求等所有被禁止的工具。
3. **规则 3 新增**：用户提到多个厂商时，必须为每个厂商调用 MCP 工具。
4. **规则 4 新增**：用户说"大概"、"差不多"不能跳过工具调用。
5. **常见错误 3 修正**：明确"告知用户网址，不要自行搜索"。

### Rationalization Table

| Rationalization | 反制规则 |
|----------------|---------|
| "我知道价格，直接告诉用户" | 规则 1：禁止知识替代 |
| "我用 WebSearch 搜一下官网" | 规则 2：禁止所有外部搜索 |
| "我用 curl 不算违规" | 规则 2：明确列出 curl |
| "我只查了阿里云，腾讯云不清楚" | 规则 3：必须完整覆盖 |
| "用户说大概就行" | 规则 4：精度要求无关 |
| "用户让我去官网查" | 规则 2：用户要求也要用 MCP |
| "价格数据不完整，我搜一下" | 常见错误 3：告知网址，不要搜索 |
